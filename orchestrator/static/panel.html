Launch milestone

Project — every launch binds to a project: the run executes in the project's work directory (which must be the root of an existing git repository — gate commits land there, state lives in <workdir>/.orchestrator/) and carries the project's standing safeguards and defaults. When a project declares several work areas a selector appears. Declare projects with “+ Project” in the sidebar.

Goal doc — when a description doc path is set, the file's content becomes the goal, snapshotted at launch.

Strategy profile — governs the run's review depth. legacy preserves the pre-reform review policy; strict / light set the doc-review threshold (what a finding must exceed to open a fix cycle vs record as tracked debt). Every profile uses the same deterministic seal. No seed is pre-selected on purpose — the choice is explicit.

Acts — implementation defaults to codex gpt-5.6-sol/max; other empty rows use their family default (claude: opus-5/max, codex: gpt-5.6-sol/max). Model options adapt to the agent; editable mid-run from the run view. The Skeleton row drives all skeleton content work — its draft, re-drafts and fixes (default: claude opus-5/max); only skeleton reviews stay on the review rows. The two review rows tune each fixed family for review rounds and delta reviews; family rotation never changes. Sealing does not launch a model.

Verification — left empty, the implementer reports the repo's official suite and the driver arms the gates with it.

New brainstorming

Project — the session runs in the project's work directory, exactly like a milestone. The target document must live inside that directory: it is the ONE artifact the discussion may write, and the only thing a stop restores.

Request — the focused result the participants should produce; it may include a question, but does not have to be one. Brief is the standing context every turn receives.

Target document — path relative to the work directory (an absolute path inside it also works). The file itself may not exist yet; the Initial Position writes it. Browse… picks an existing document; New… picks an existing directory and proposes a fresh session folder inside it (bs-<stamp>/DECISION.md, editable) — the missing folders are created at launch, so no directory ever has to be made by hand. Without New…, the target's parent folder must already exist.

Participants — the Initial Position proposes, the Contrary Position tries to disprove it, and Dante asks common-sense anti-drift questions. Dante does not vote.

Closure — unanimity needs every position to accept the exact final proposal; majority needs a strict majority. A tie, or no agreement at the round limit, closes as an irreducible gap. The coordinator records the result and never chooses a side.

Rounds — the hard ceiling on discussion rounds; the session fails rather than exceed it.

Project
    

  

    
Work directory — the git repo runs of this project execute
      in. Changing it (or the read-only roots) re-declares the area: the
      version bumps, the status returns to pending, and the next
      bound launch validates the real roots and confirms ready.

    
Read-only roots — sibling repos workers may READ for
      evidence (dependencies, consumers); they are never editable by
      workers.

    
Safeguards — standing law rendered into every bound worker's
      prompt. Version is operator intent: bump it on substance changes so
      runs re-record the safeguard. Run-scoped amendments win on
      conflict.

    
Defaults — a JSON object merged beneath every bound launch of
      this project. Configuration outlives runs; edits bind the next launch
      or worker call.
