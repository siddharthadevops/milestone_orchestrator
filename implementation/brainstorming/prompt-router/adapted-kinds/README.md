# Adapted Kinds — Current Prompts Restructured for the Prompt Router

Status: **binding seed corpus for this goal; assembled by the pure router but
not yet wired to runtime consumers** — the
target prompt set for the prompt-router milestone defined in
[`../goal.md`](../goal.md), with
[`../prompt-content-milestone.md`](../prompt-content-milestone.md) as its
design rationale and [`../current-prompts.md`](../current-prompts.md) as the
captured evidence it was pruned from.

## Layout

- One directory per PROCESS, one JSON per kind:
  - `milestone/`: `draft_skeleton`, `draft_slice_note`, `implement`,
    `review_round`, `delta_review`, `reclassify`, `fix_findings`,
    `suite_checkpoint`, `merge_repair`.
  - `brainstorming/` (the session executor's kinds): `discussion_turn`
    and `questioner_turn` (Dante). (production_effect and the closure
    kinds are retired — decisions 42-43.)
  - `shared/shared.json`: the cross-kind units and contract sections.
  Rendered examples (`<kind>.prompt.txt`) sit beside their JSON; the
  read-only Contrary variant also has `discussion_turn.contrary.prompt.txt`,
  and the direct-call repair branch has `merge_repair.agent_call.prompt.txt`.
- `shared.json` holds every text block used by more than one kind (units and
  contract sections). Kind files reference them with `{"ref": "<id>"}`; the
  router inlines them when answering. Storage keeps refs; the wire response is
  always fully assembled.
- `<kind>.prompt.txt` is the rendered example each JSON produces, generated by
  `render_examples.py` from the JSONs with frozen representative values. The
  milestone examples retain captured payloads where they still match the
  target; session examples deliberately use the target one-repo/Git topology,
  not the retired captured work area. `current-prompts.md` remains the untouched
  historical evidence. Regenerate after editing any JSON.

## Conventions

- **Text as line arrays.** Every text is a JSON array of strings, one per line;
  the consumer joins with `\n`. This keeps the stored JSON readable and diffable
  without markdown files.
- **Variables.** `{{name}}` placeholders. Each unit declares its variables:
  `"required": true` → missing value is a consumer error (loud);
  `"required": false` → the consumer substitutes or, when the whole unit exists
  only to frame the variable, drops the unit (`"drop_unit_if_absent": true`);
  `"default": "…"` → value used when the consumer passes none. Live implement
  size targets `soft_lines`/`hard_lines` are supplied by that call's meter and
  their unit is absent on the unmetered stabilization call.
- **Units per kind.** `instructions` (ordered `parts`), `questions` (the NEW
  output-answered battery: `intro` lines + `items` of `{id, text}`; renders as
  a QUESTIONS block before the contract and lands in the output's `questions`
  array, checked for one non-empty answer per mounted id with no length
  ceiling; kinds without authored items stay blank), and
  `output_contract` (ordered `sections`).
- **Refs can pin per-kind constants.** `{"ref": "common_fields", "defaults":
  {"status_vocabulary": "…"}}` fixes a shared unit's variable to a kind-level
  constant; the consumer supplies only what remains open.
- **Route-mounted parts.** `{"ref": "…", "mount": ["target:document"]}` tags a
  part for canonical route/seat coordinates. The router derives these tags;
  callers never pass optional switches. Everything else is unconditional.
- **Variants.** A part `{"one_of": "<group>"}` selects one entry from the kind's
  `variants.<group>` by a consumer-supplied key (today: the discussion turn's
  per-seat role stance).
- **Contract sections.** Each section has an `id` and text. The consumer
  assembles the sections it needs and MAY append its own registered sections.
  Validation rules live in code, keyed by section id, and validate exactly the
  registered subset of the assembled ids. Stored unknown ids are served but
  ignored; consumer-appended unknown ids are refused. The prose here never
  carries a section another kind owns.
- **Materials layer the complete base.** Every non-empty material id is a valid
  lookup key. The resolver mounts the base job cell and then its exact override
  when one exists; no match returns the unchanged base without an error or
  fallback note. This borrows staffing's precedence only, not its material
  admission/catalogue semantics. This seed ships no real overrides, while resolver tests use a
  synthetic `code` layer to pin the data-only extension seam.
- **Dynamic payloads are variables, never stored text.** Operator amendments,
  project context, adjudicated rejections, deferred
  debt, queued findings, and catalogues are all `{{variables}}`.
  Only their framing lines are template text.
- The existing engineering gates (victim/machinery/…, consumers_touched/…)
  are **task description**, named **DUE DILIGENCE**: they live inside
  `instructions` and are answered in the DOCUMENT only. **QUESTIONS** is the
  separate first-class battery answered in the output JSON (`questions`
  array, explanatory free text with exact ids and non-emptiness
  machine-checked) — the two never share a name.

## Deliberate adaptation decisions (vs the captures — veto any of these)

1. **The all-kinds mega contract is dismantled.** Every kind now carries only
   its own contract sections. (The review/fix/reclassify captures already did
   this; the author kinds shipped a 187-line union.)
2. **`draft_skeleton` loses `need_rethink` and `retry` text** — the contract
   itself says neither status is eligible for that kind.
3. **`reclassify` receives the complete current amendment set** — Slice 06 and
   operator amendment A4 supersede the earlier omission decision. The rater is
   report-only, but mutable operator authority still reaches every physical
   judgment attempt alongside project context, its finding, and process law.
4. **`review_round` / `delta_review` share one contract** (the captures were
   already byte-identical) and share the judgment rubric / severity battery.
5. Conversational artifacts inside amendment PROSE (e.g. "Stop discussing it.")
   are untouched: amendments are variables — operator data, not template text.
6. **fix_findings' ADVERSARIAL block now names FIX VERDICT ACCOUNT** — the
   capture said "every item in the JUDGMENT RUBRIC", a block that does not
   exist in the fix prompt (that is the reviewers' name for it).
7. **The fix contract's `slices` clause is folded into `fix_results`** as
   prose referencing the skeleton plan shape, instead of repeating the full
   JSON shape a fourth time; the old "active block above" parenthetical no
   longer listed `slices`/`suite_command` (each had its own clause at this
   stage; suite reporting is retired by 71).
8. **need_rethink prose exists once per style** — the verbose author section
   (`need_rethink_author`) and the compact review/fix snippets; the capture
   spelled it three times inside fix_findings alone. The round limit is always
   `{{brainstorming_max_rounds}}`, single-sourced (the `__ROUNDS__` doctrine).
9. **The old battery's JSON output is REMOVED** (operator decision,
   2026-08-22). The Question Battery is written into the document only,
   policed by reviewers as before; the `battery` array, its BATTERY OUTPUT
   contract section, and the machine validation (exact ids, clips) retire —
   no finding of that class ever occurred. In its place, the new `questions`
   battery of the two doc-author kinds carries one item (`battery_count`:
   "How many Question Battery answers did you write into the document?");
   the only check is that it was answered. Code-side (validate_battery,
   battery_questions plumbing) this retires when the router ships — a
   milestone change, not an edit here.
10. **PLANNING CONTEXT is folded into PROCESS AUTHORITY** (operator order,
    2026-08-22): the vendored-instructions bullet now also declares
    brainstorming/`_drafts` material non-canonical with the Adopts / Revises /

    bullet (run local/focused checks) moved into its build instructions.
    Note: process_authority ships to every kind, so reviewers/fixers/rater now
    read this sentence too (the old block reached only the three authors).

    credentials, or personal data — is now a single line under the prompt
    header. "Apply the change; never merely describe it" also fell: a
    describe-only reply already fails the contract's work claims
    (`files_changed`/`artifact`).

    ignore agent instruction files and the entire .orchestrator/ directory —
